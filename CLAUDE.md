# CLAUDE.md

> **Last Updated:** 2026-09-07

Правила для агентов-разработчиков в проекте Гоко. Канонический файл: если
`AGENTS.md` или доки расходятся с ним, прав этот файл, если founder не
сказал иначе для текущей задачи.

## О проекте

Гоко — голосовой соперник по го на физической доске 13×13. Телефон лежит
рядом с доской, человек говорит «давай партию», «дэ четыре», «кто впереди»,
Гоко отвечает голосом, экран показывает доску и ленту диалога. Позицию и
ходы ведёт KataGo, разговор — OpenAI Realtime через LiveKit Agents.

- Спека (читать первой): `docs/superpowers/specs/2026-09-07-goko-voice-go-opponent-design.md`
- Текущий фокус и следующий шаг: `docs/NOW.md`
- Карта документации: `docs/README.md`
- Решения после спеки: `docs/decisions/`
- Стадия: 0 (спайк) не начата; кода ещё нет `[WIP]`

## Стек

TypeScript, Node 22, npm workspaces. Hono (game-server), Vite + React (web),
`@livekit/agents` + плагин OpenAI (voice-agent), KataGo analysis engine
(go-engine), zod (протокол). Инфраструктура: один VPS, Docker Compose,
Caddy, LiveKit. Никаких БД в v1.

## Структура

```
packages/protocol    zod-схемы операций, ошибок, событий; HTTP-клиент
packages/go-core     правила доски, координаты, счёт, SGF
apps/game-server     сессии, партии, места, SSE, вызов движка, токены LiveKit
apps/go-engine       обёртка над KataGo: genmove / analyze / score
apps/voice-agent     воркер LiveKit Agents: инструменты, промпт
apps/web             одна страница: доска, лента, микрофон
apps/mcp-server      стадия 2
infra/               compose, Caddyfile, livekit.yaml, scripts/
scripts/             doctor, smoke, chat — проверки из CLI
docs/                спеки, планы, решения, runbook
```

## Правила

1. **Спека — источник правды по протоколу и поведению.** Расхождение кода
   со спекой — либо баг, либо решение в `docs/decisions/` и правка спеки.
2. **Правила го живут только в `packages/go-core`.** Веб рисует присланный
   массив, агент ничего не помнит о позиции: каждая реплика — из инструмента.
3. **Тесты до кода.** Unit для `go-core`, сценарные для `game-server`,
   контрактные для `go-engine` при `KATAGO_BIN`, замоканный клиент для
   `voice-agent`.
4. **Секреты не в git.** `.env` только локально и на VPS; в репозитории —
   `infra/.env.example` и указатели. Значения переменных не печатать в логи
   и не вставлять в доки.
5. **По явной просьбе founder'а в текущей сессии:** деплой (`deploy.sh`),
   любые действия в Hetzner, DNS, tailnet, аудио-тесты с телефона (стоят
   денег). Разрешение на одно действие не распространяется на следующее.
6. **Личная инфраструктура founder'а** (VPN-сервер, релей, ПК) в доках не
   описывается: ни адресов, ни хостнеймов. Репозиторий публичный.
7. **Процесс.** Правка в существующем потоке — без спеки. Новая подсистема
   или интерфейс — brainstorming → спека → план (superpowers). В конце
   сессии обновить `docs/NOW.md`: что сделано, что открыто, следующий шаг.
8. **Стиль.** Доки, комментарии, коммиты по-русски; код и идентификаторы
   по-английски. Маркеры `[OK] [!] [FIX] [X] [WIP] [TODO]`. Без эмодзи.
   Коммит: `<область>: <что сделано>`.

## Роль агента

Founder — преподаватель математики, учится разработке. Сначала ответ или
результат, потом варианты с trade-offs; рекомендация первой. Батчи вопросов
вместо потока; закрытые решения не пересматривать без новых фактов. Сроки
в днях.

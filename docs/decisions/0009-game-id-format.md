# D-0009: формат идентификатора партии и сессии

- Дата: 2026-09-13
- Решили: founder + агент (пакет правок 12b, стадия 1)
- Уточняет: спека, раздел 4

## Контекст

Идентификатор партии — имя файла снапшота `data/games/<id>.json`. Имена
устройств Windows (`con`, `nul` и другие) и длинные имена ломают запись.
Случайная часть в 3 байта давала заметную вероятность совпадения среди
тысячи id в одну миллисекунду; совпадение перезаписало бы снапшот чужой
партии.

## Решение

- `newId()` = base36 от `Date.now()` + 6 случайных байт в hex (12 символов);
  сейчас 20 символов, id сортируются по времени создания.
- `GameStore.save` принимает только `^[0-9a-z]+$` длиной до 64, не `con`,
  `prn`, `aux`, `nul`, `com0–com9`, `lpt0–lpt9`; иначе `bad_request` с
  `details.id`.
- Старые снапшоты с 14-символьными id читаются: `load` id не проверяет.
- `create` не выдаёт занятый id: если сгенерированный id уже есть среди
  партий или создаваемых прямо сейчас, он генерируется заново, до 8 попыток
  (дополнено по широкому ревью ветки, 14.09).

## Последствия

- При 48 битах на миллисекунду совпадение практически невозможно, повтор
  генерации — дешёвая страховка: восемь занятых подряд id — ошибка сервера
  `internal`, а не перезапись чужого снапшота.

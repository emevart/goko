# Журнал решений

Решения, принятые после спеки и меняющие курс. Решения до старта проекта —
в разделе 2 спеки, здесь их не дублируем.

## Что фиксировать

Тест двух вопросов: (1) будет ли будущий агент или founder действовать иначе,
не зная решения; (2) цена незнания выше пяти минут чтения. Оба «да» —
фиксируем. Обязательно: трудно обратимые решения, отказ от очевидной
альтернативы, изменение протокола `packages/protocol`, изменение
инфраструктуры или расходов.

Не фиксировать: локальные обратимые выборы, читаемые из кода и коммита.

## Формат

Файл `NNNN-slug.md`, нумерация сквозная с `0001`.

```markdown
---
status: living
area: architecture | product | infra | process
updated: YYYY-MM-DD
---

# D-NNNN: <название>

- Дата: YYYY-MM-DD
- Решили: founder | founder + агент
- Заменяет / уточняет: D-XXXX или раздел спеки

## Контекст
## Решение
## Последствия
```

Пишет агент по итогам обсуждения, founder ревьюит. После записи — правка
соответствующего раздела спеки со ссылкой на решение.

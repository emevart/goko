# D-0015: явный разговор и интеграция GPT-Live

- Дата: 2026-09-15.
- Решили: founder поручил реализацию после повторной записи;
  детали интеграции определяются проверками координатора и исполнителя.
- Уточняет: D-0001, D-0004, D-0011, D-0013, D-0014.
- Текущая готовность и проверки: [NOW](../NOW.md) и
  [приёмка](../research/2026-09-15-live-polish-acceptance.md).

## Контекст

Повторная партия выявила автоматический вход, прерывания на посторонние
звуки, рассогласование записи и применение гипотетической координаты.
Доступ к GPT-Live подтверждён реальным ответом с инструментом. Простая
замена имени модели не переносит жизненный цикл и контекст Realtime.

## Решение

Вход в разговор происходит по первому сообщению или голосовой кнопке.
Микрофон захватывается из жеста, полученный track используется при публикации.
Завершение закрывает разговор и платную сессию, но сохраняет игру.
Повторный вход получает свежий токен и отдельное поколение dispatch через
POST /api/sessions/:sessionId/conversation. Повторы не должны создавать
несколько агентов или возвращать завершённое поколение поверх нового.

GPT-Live — отдельный VOICE_MODE=live с marin и backend gpt-5.6-luna.
Голос получает инструкции стиля и делегирования, backend — правила и tools.
Realtime и pipeline сохраняются для отката. Разговор имеет отдельный
конфигурируемый предел длительности, который завершает сессию; таймер
автоматического переподключения SDK не является ограничителем расходов.
По умолчанию VOICE_SESSION_MAX_MS=3600000 (час), допустимы 1–120 минут.
Переход опубликованного приложения на Live требует явного VOICE_MODE=live
при согласованном развёртывании. Значение по умолчанию realtime сохраняет
предсказуемое поведение существующих установок. Chat в Live продолжает
генерировать речь у провайдера при выключенном локальном воспроизведении;
отключённый микрофон не означает бесплатную сессию.

В Live перебиванием управляет модель, локальный VAD не обрезает playout.
Для событий доски используется добавление фактов с gameId/revision;
переписывание истории Realtime из D-0013 к Live не применяется. Написанный
текст направляется в Responses через response.item.create и response.create
с согласованием ожидающих результатов tools. Это официальный typed-путь;
commentary само по себе не доказывает запуск backend или произнесение ответа.
При отключённом микрофоне локальный захват, provider mute и продвижение
аудиопотока проверяются отдельно. Синтетическая тишина 24 кГц mono поступает
кадрами по 100 мс, пока реальный вход выключен. При включении микрофона
этот источник останавливается до возобновления реального аудио, при закрытии
разговора — освобождается. Контрольный прогон без кадров выполнил инструмент,
но не дал речи: mute сам по себе не заменяет входные часы.

Мутация требует актуального подтверждённого текста человека и согласованных
аргументов. Событие доски не создаёт такое намерение. Уточнение 15.09 после
регрессии «мой первый ход чёрными К4» и прямой просьбы founder дать модели
больше свободы: намерение, отрицания и самоисправления определяет модель по
контексту. Грамматический whitelist удалён для всех мутаций. Код проверяет
источник полной реплики, одноразовость и совпадение распознанных координат;
сервер сохраняет проверку правил, очереди и ревизий. Несколько координат в
самоисправлении не запрещены. Незнакомое произношение трактует модель.
Это осознанный перенос семантической проверки в модель, не детерминированная
гарантия отсутствия ошибочных ходов. Отрицательные примеры проверяются через
`scripts/eval-voice-intents.mjs` с реальными production schemas и backend.
Изменение настроек при новой партии выполняется только по просьбе человека,
неуказанные rank/komi модель должна опускать.

Из отображаемой пользовательской расшифровки и ledger убираются известные
служебные метки шумов, включая разрыв перед закрывающей скобкой. Это не
фильтр входящего аудио: реакции Live на кашель остаются модельным поведением.
Оценки содержат gameId/revision; сравнение ходов использует настоящие
продолжения KataGo. Дополнительный анализ не заменяет выбор по humanPolicy
необъявленным выбором самого сильного хода.

Запись обеих сторон использует общие часы Web Audio и mono destinations.
Завершение сообщения в истории — метаданные, не источник замены живой
расшифровки и не доказательство, сколько аудио человек услышал.

## Последствия

Нужны согласованные версии web/server/voice/protocol. Новая публикация
выполняется отдельным действием после готовности пакета и разрешения founder.
Естественность, кашель, реальные паузы и разрешения мобильного браузера
остаются предметом телефонной приёмки даже после автоматических проверок.

Ограничение SDK 1.8.1: raw typed item текущего Responses-разговора не попадает
в локальную replay history плагина. При восстановлении транспорта эта
написанная реплика может выпасть из контекста модели. Это не потеря видимой
ленты приложения и не повторная мутация: намерение проверяется отдельно.
Добавлять пользовательский текст через appendThinking как developer-правило
без отдельной проверки reconnect не решено; восстановление typed history
остаётся отдельным пунктом улучшения.

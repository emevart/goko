# Единый разговор, диагностика и история партии

Основание: отзыв founder'а 14.09, разбор
`docs/research/2026-09-14-voice-feedback.md`, поручение 15.09 продолжить
самостоятельно и разрешение начать новую проверочную партию. Это разрешение
на реализацию следующих требований с выбором обычных деталей координатором;
способ — принятый в проекте subagent-driven. Прежняя спека сохраняется, этот
документ заменяет её положения о раздельном UI Голос/Чат и добавляет redo.

## Цель

Сохранить минималистичную доску и сделать общение непрерывным: человек всегда
может писать, включить голос в том же разговоре и понять, слышит ли его Гоко.
Оборванные реплики должны быть заметны, объяснения — опираться на позицию.

## Интерфейс

Широкий экран: доска слева, разговор справа. Телефон: доска над разговором,
без горизонтального скролла на 360 px. Верхняя панель: название, новая партия,
пас, сдача, назад и вперёд; настройки новой партии раскрываются по кнопке.
Поле текста всегда видно. Кнопка голоса включает/выключает микрофон и звук,
сохраняя существующий транспортный атрибут goko.mode ради совместимости.
Нет двух вкладок разговора. Ошибка autoplay не считается успешным звуком:
пользователь видит кнопку включения/повтора воспроизведения.
Микрофон включается только явной кнопкой голоса/повтора, не произвольным
касанием доски или настроек. Сохранённый voice-pref не означает разрешение
самостоятельно включать микрофон при загрузке страницы.

Орб показывает состояния подключения, слушания, обработки и речи.
Когда доступны аудиодорожки, амплитуда связана с реальным аудио. Состояние
получается из LiveKit, а не из случайного таймера. Поддержать reduced motion,
клавиатуру и текстовые названия кнопок для screen reader.

История показывает ходы по номерам и цветам, последний ход выделен. В этой
итерации история — список; отдельный режим просмотра произвольной позиции
не нужен. Назад/вперёд изменяют текущую позицию через сервер.

## Undo, redo и темп

Сохранить семантику undo: обычно пара ходов, во время ответа движка — один
ход человека, после счёта — два паса; после сдачи undo по-прежнему запрещён.
Redo восстанавливает ровно ранее отменённую порцию, включая прежние координаты,
время ходов и финальный счёт, без нового вызова движка, если ответ уже был
сохранён. Несколько undo/redo работают последовательно и после загрузки
снапшота. Старые снапшоты без истории читаются как с пустой историей.
Новый успешный ход/pass/correct/resign очищает будущую ветку; отказ операции
историю не меняет. Смена ранга сохраняет историю. Ревизия при любом undo/redo
растёт; поздний ответ ранее отменённого поиска никогда не применяется.

Веб и голос передают expectedRevision для undo/redo. Конкурирующие операции
на одной исходной ревизии не применяются обе; revision_conflict не повторяется
вслепую. Две последовательные команды на уже разных ревизиях могут быть
намеренными и не склеиваются эвристикой по времени. Поздний результат
голосового инструмента старой партии не изменяет флаги или gameId новой.
В пределах одной партии ответ старой ревизии также не сбрасывает флаги,
установленные более свежим событием SSE; отмена кнопкой и возврат голосом
используют актуальную общую ревизию.
Для точного различения создания партии кнопкой и голосом NewGameRequest
получает via с прежним значением по умолчанию api. Веб передаёт tap, агент —
voice; сервер переносит via в state.updated/new. Одновременные startGame в
одном AgentState запрещены. Источник не выводится из порядка прихода событий;
после ожидания HTTP результат сверяется с текущими gameId и поколением.

Добавить POST redo, схемы, тип ошибки nothing_to_redo, клиент и событие причины
redo. Правила доски остаются в go-core, восстановление через replay.

В production минимальная пауза перед применением ответа движка — 1500 мс от
запуска его задачи (если поиск дольше, дополнительной паузы нет). Значение
ENGINE_MOVE_DELAY_MS настраивается 0–5000; в сервисных тестах ноль. Пауза
отменяема, не держит мьютекс и не тормозит undo/resign/закрытие сервиса. Статус
UI «Гоко готовит ход» честно покрывает поиск и паузу. Никаких выдуманных
рассуждений ради анимации; реплика хода идёт после применения состояния.

## Голос и содержательность

Промпт сохраняет гарантии операций, доверенные события и произношение координат.
Снять глобальное ограничение двух предложений. Для вопроса новичка — конкретный
ответ с целью, влиянием на группу и ближайшим последствием; оценочные числа не
объявлять причиной хода. Для обсуждения позиции запрашивать актуальные данные,
не придумывать связь групп. Центр доски 13×13 — G7, не E11. Тёплый спокойный
тон с естественным темпом, без обязательных смешков и слов-паразитов.

Озвучивание событий остаётся коротким и без повторного вызова игровых
инструментов. Вопрос «почему» обсуждается отдельно. Кнопка/голосовая команда
redo использует один серверный контракт.

Настроить поддерживаемое шумоподавление/turn detection по проверенным API,
не обещая фильтрацию кашля только промптом. Сохранить настоящее перебивание.
События остановки/прерывания выводятся в диагностике; явно прерванная реплика
не выглядит законченной. Не обрезать по недостоверной эвристике весь текст.

GPT-Live — исследованный кандидат, но не обязательная миграция этой итерации:
новый endpoint и модель не включаются без подтверждённого доступа. Можно
проверить доступ read-only списком моделей, не считать это доказательством
работоспособности live-сессии. Базовый путь остаётся проверяемым Realtime.

## Запись для диагностики

В первой версии запись выполняет браузер по явной кнопке, без нового Egress
или серверного хранения. Сохраняются две отдельные аудиодорожки (микрофон и
полученный голос Гоко), плюс JSON с относительным временем, событиями связи,
плеера, реплик, перебиваний и ревизиями/ходами. В UI видны индикатор и таймер,
остановка и ссылки скачивания файлов. Неподдерживаемый MediaRecorder/кодек,
отсутствующая дорожка или ошибка приводят к понятному отказу, а не фиктивной
записи. Формат выбирается по isTypeSupported; не обещать WAV всем браузерам.

Запись ограничена 20 минутами; 64 MiB суммарно — порог автоматической остановки,
не предел внутренней памяти MediaRecorder (запоздавший финальный chunk может
его превысить). Данные получаем порциями примерно раз в секунду, показываем
фактический размер и причину остановки. Журнал ограничен 10000 событиями,
8000 символами payload и 4 MiB JSON с явной отметкой отсечения.
Отключение голоса/комнаты и смена дорожки завершают запись
с сохранением доступного результата. Состояние старой комнаты не смешивается
с новой. Клоны дорожек/обработчики/таймеры освобождаются, основные дорожки
разговора не останавливаются. По окончании остановленной записи файлы можно
скачать или удалить из памяти. Перезагрузка страницы теряет несохранённую
запись — это явно написано рядом со скачиванием. Сервер ничего не хранит:
ранее предложенные 7 дней здесь не применяются. Доступ к скачанным файлам
определяется устройством пользователя. Уже прошедшее аудио не восстанавливается.

## Приёмка и границы

Уточнения после ревью: аудио/расшифровки/события Гоко принимаются только от
участника с kind AGENT, привязанного identity+SID к поколению комнаты.
Исключение только для расшифровки самого игрока: LiveKit Agents передаёт её
от логического senderIdentity текущего телефона. Такой поток принимается
как речь игрока при совпадении local identity, who=me и поколения комнаты.
Чужой sender не становится доверенным только из-за атрибута track id.
События goko.conversation сохраняют строго agent-only проверку.
Рестарт сбрасывает dedupe producer, новая комната не дописывает старую запись.
Controlled teardown сначала завершает запись; неожиданный disconnect сохраняет
доступную часть. Ошибка воспроизведения имеет отдельное состояние от сетевой.
Undo доступен во время ожидания engine reply, остальные дублирующие операции
заблокированы; поздний HTTP-ответ старого хода не отменяет успешный undo.

Нужны meaningful unit/scenario tests для восстановления истории, гонок
отмены, API, записи/очистки ресурсов и обработки прерываний, полный check и
smoke. В браузере: мобильная/широкая раскладка, отправка Enter при голосе,
контролы/история, состояния ошибки аудио, запись с тестовыми дорожками и
скачиваемые данные. Один разрешённый живой прогон после бесплатных проверок;
микрофон отсутствующего founder'а не включать. Реальные тембр, кашель и
поведение Safari остаются проверкой founder'а, если нет реального устройства.
Новые секреты, покупка доступа, изменения DNS/Hetzner не нужны. Повторный
production deploy остаётся отдельным шагом после готового проверенного пакета.

# Оркестрация: отделы, роли, журналы

Как устроена разработка Гоко силами агентов. Решение founder'а 08.09:
координатор распределяет работу по субагентам, не более двух одновременно.

## Роли

| Отдел | Роль | Что делает | Модель |
|---|---|---|---|
| Координация | координатор | держит план, брифы, журналы, ревью, решения; сам код не пишет | Opus 5 |
| Архитектура | верификатор | проверяет внешние факты до кода: версии пакетов, API библиотек, имена релизов | Opus 5 |
| Разработка | исполнитель | одна задача плана: тесты, код, прогон, коммит, самопроверка, отчёт | Opus 5 |
| Качество | ревьюер задачи | сверяет диф с брифом (спека) и качеством кода; вердикт по обоим | Opus 5 |
| Качество | ревьюер ветки | один широкий обзор всей ветки перед слиянием | Opus 5 |
| Инфраструктура | инженер VPS | bootstrap, compose, деплой, проверки хостов | Opus 5 |
| Решения | консультант | короткие развилки, где нужен свежий взгляд | Fable 5.1 |

Роли — это не люди, а инструкции в брифе. Один субагент = одна роль = одна
задача. Контекст между ними не наследуется: всё нужное передаётся файлами.

## Правила

1. **Не более двух субагентов одновременно.** Двух исполнителей параллельно
   не бывает: конвейер «исполнитель задачи N + ревьюер задачи N-1» или
   «исполнитель + верификатор только на чтение».
2. **Исполнитель не вызывает субагентов.** Ревью приходит от координатора.
3. **Бриф — единственный источник требований.** Точные значения только в нём;
   весь план субагенту не передаётся.
4. **Обмен через файлы.** Брифы, отчёты и пакеты ревью лежат в
   `.superpowers/sdd/<план>/` (вне git), а не в переписке.
5. **Цикл правок — до пяти кругов** на задачу; дальше координатор выносит
   решение и записывает его в журнал.

## Журналы

| Журнал | Где | Кому |
|---|---|---|
| Механический (SDD) | `.superpowers/sdd/<план>/progress.md`, вне git | координатору: что сделано, какие коммиты, какие решения |
| Проектный | `docs/journal/` в git | founder'у: одна строка на задачу, сохраняется навсегда |
| Состояние | `docs/NOW.md` | обоим: фокус, открытые вопросы, следующий шаг |

Механический журнал переживает потерю контекста и является картой
восстановления: коммиты, названные в нём, есть в git. Проектный журнал
коммитится вместе с работой.

## Что остаётся за founder'ом

Аудио-тесты с телефона, подтверждение спорных развилок продукта и всё, что
стоит денег сверх согласованного. Действия на VPS, в DNS и Hetzner — по
явной просьбе в текущей сессии (правило 5 `CLAUDE.md`).

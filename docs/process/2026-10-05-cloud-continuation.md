## Что выяснил аудит свежего main

`get_position` уже строит ASCII и список камней из одного серверного снимка.
`Analysis.gameId/revision` обязательны; analyze проверяет expectedRevision
до и после движка. Агент отбрасывает поздний анализ и кеширует его по ревизии.
Явный голосовой разговор и включение/выключение микрофона тоже уже есть.
Эти потоки не переписывать на основании замечаний к старой stage0.

Полезная оставшаяся регрессия: HTTP analyze(expectedRevision=R) удерживается
фейковым движком, HTTP undo завершается параллельно, затем analyze возвращает
409 revision_conflict. Свежий анализ новой ревизии проходит. Использовать
настоящие router/service/client; синхронизация deferred promise, без sleep.

## Ближайшая продуктовая итерация

Это развитие существующих потоков стадии 1; новая подсистема не вводится.
Тесты до изменений, затем независимое ревью Astra и фактические проверки.

1. Добавить read-only `repeat_last_move`: «не расслышал, повтори свой ход».
   Один GET текущей игры, последний записанный ход места engine из актуальной
   истории, готовое русское произношение, gameId/revision; существующие guards
   gameGeneration/observedRevision. После undo не произносить удалённый ход,
   после correct повторять новый. Пас повторяется словом и не вызывает pass.
   Pending обозначает, что новый ответ ещё ожидается. Пустая игра/два человека/
   смена игры/ошибка GET — понятный отказ. Никаких play/correct/pass/undo/redo/
   resign/newGame/analyze и изменений awaitingReply/lastTap/announcedFinish.
   Подключить существующую очередь tools и отображение состояния орба.
   «Верни отменённый ход» остаётся redo; неясное «повтори» требует уточнения.
2. Уточнить в backend и Live инструкциях: отдельно названная неоднозначная
   буква «и»/I требует уточнения, а не угадывания E. Не запрещать союз «и» в
   составной просьбе; «е»/Е по-прежнему означает E. Не вводить grammar whitelist
   и не добавлять И→E в ядро. Prompt/unit не доказывают выбор реальной модели.
3. Полировать текущую страницу: более читаемые камни, мягкая рамка/тень доски,
   ясная иерархия статуса, длинный отказ без обрезки, аккуратные focus/hover и
   кнопки. Сохранить геометрию/жест hold-drag, метку последнего хода, территорию,
   живой орб, цвета его состояний, reduced-motion и WebGL fallback. Проверить
   360×640, 390×844, 1440×900, светлую/тёмную тему, открытые панели/диалог.
4. Синхронно поправить изменившийся раздел спеки/журнал решения и NOW.
   Сделать reviewable commit/PR; не merge и не deploy без отдельного запроса.

## Разрешённые платные проверки этой итерации

Founder явно разрешил существующий OPENAI_API_KEY и его сохранение как
сетевого секрета приватного окружения goko только для api.openai.com.
Значение не хранить в репозитории и не выводить. Сетевой секрет приходит
в процесс как placeholder; настоящий ключ подставляет облачный прокси.

Лимит: не более двух коротких OpenAI Realtime/GPT-Live сеансов, суммарно
не более 180 секунд подключения. На момент передачи использовано 0.
Жёсткий таймер и finally close, длительность каждого сеанса в отчёте.
Не запускать полный платный корпус по старым бюджетам. Проверить D4,
повтор услышанного хода без изменения доски, неоднозначную «и» без мутации,
факт позиции без выдуманного будущего хода. По возможности настоящий voice
stack с fake игровым клиентом без VPS/LiveKit комнаты. Если облачный прокси
не поддерживает нужный WebSocket/SDK путь — зафиксировать ограничение, не
добавлять raw key, LiveKit/VPS секреты или новые платные обходы автоматически.

Телефон, STT реального аудио, кашель/наложение речи и голосовое качество не
считать проверенными по текстовому запросу либо mock LiveKit. Сети/бинарник
KataGo не скачивать для бесплатного cloud контура. Локально настоящий KataGo
прошёл пять контрактных тестов до передачи; это отдельное доказательство.

# Отчёт задачи 1 — redo и темп движка

## Результат

- Добавлен полный контракт `POST /api/games/:id/redo`: схемы запроса и ответа,
  HTTP-клиент, маршрут сервера, причина события `redo`, ошибка
  `nothing_to_redo` и русский текст ошибки.
- `GameState.canRedo` сообщает клиентам о доступном возврате без отдельного
  запроса.
- Undo сохраняет порции ходов в хронологическом порядке вместе с прежним
  `result`, если партия закончилась счётом. Redo переигрывает сохранённые ходы,
  сохраняет их координаты и время, увеличивает текущую revision и не вызывает
  движок повторно для уже сохранённого ответа.
- История redo записывается необязательным полем `redoHistory` рядом с состоянием
  в снапшоте. Старые снапшоты без поля загружаются с пустой историей.
- Несколько undo/redo работают как стек и переживают перезапуск. Успешный новый
  ход, pass, correct, resign, ответ движка или новый счёт очищают будущую ветку;
  неуспешная операция её сохраняет. Смена ранга историю сохраняет.
- Undo, redo, correct, resign и смена ранга отменяют устаревшую фоновую задачу.
  Если redo вернул только человеческий ход, запускается новый поиск.
- `engineMoveDelayMs` по умолчанию равен нулю при прямом создании сервиса.
  Боевой `start-server` читает `ENGINE_MOVE_DELAY_MS`, по умолчанию 1500 мс,
  и принимает только целые значения 0–5000. Пауза считается от начала поиска,
  выполняется вне мьютекса и прерывается abort/закрытием.
- Переменная добавлена в `infra/.env.example`, Docker Compose и VPS runbook.
  Smoke принудительно использует ноль для быстрого детерминированного прогона.

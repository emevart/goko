# Спайки стадии 0

Одноразовые скрипты для проверки фактов перед стадией 1. В продакшен-код не
идут: стадия 1 переписывает проверенное в `apps/`.

- `katago-bench.mjs` — замер analysis engine KataGo на доске 13x13:
  `humanPolicy` (1 visit), genmove (10), analyze (50), score (400).

  ```bash
  node spike/katago-bench.mjs --bin <katago> --model <main> --human <human> [--config <cfg>]
  ```

  Без `--bin` берётся `KATAGO_BIN`, без `--config` —
  `apps/go-engine/config/analysis.cfg`. Сети и бинарь качаются по
  `apps/go-engine/models/README.md` и в git не попадают. Если в выводе
  `human=NO`, в `-human-model` подан не тот файл или KataGo старше 1.15.

## Голосовой спайк

- `agent.ts` — воркер LiveKit Agents с OpenAI Realtime: голос по-русски,
  инструмент `play_move` без движка (отвечает ходом из списка-заглушки),
  лог реплик и вызовов в `spike/log.jsonl` (в git не идёт).
- `token.mjs` — токен участника с диспетчеризацией агента `AGENT_NAME`.
  Ссылку на страницу спайка (`#url=...&token=...`) **не печатает**, а пишет
  в `spike/last-url.txt` (в git не идёт, режим 600); в stdout уходит только
  имя комнаты и путь к файлу.
- `chat.mjs` — текстовый диалог с агентом без микрофона: stdin уходит в
  `lk.chat`, расшифровки печатаются в stdout. Нужен, когда проверяется
  логика, а не распознавание речи.
- `public/index.html` — одна страница без сборки: микрофон, лента
  расшифровок, отправка текста в `lk.chat`.
- `phrases.md` — 30 фраз с ожидаемыми координатами для проверки русского
  распознавания.

```bash
npm run agent -w spike   # регистрирует воркера, ждёт задания
npm run chat -w spike    # текстовый диалог в новой комнате
npm run token -w spike   # печатает комнату, ссылку кладёт в spike/last-url.txt
```

Все три команды читают `.env` в корне репозитория: `LIVEKIT_URL`,
`LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET`, `OPENAI_API_KEY`, `WEB_HOST`,
`AGENT_NAME`. Значения не коммитить и не печатать. У `chat.mjs` есть ещё
`CHAT_QUIET_MS` (тишина после конца ввода до разрыва комнаты, 5000 мс) и
`CHAT_MAX_WAIT_MS` (потолок ожидания, 60000 мс).

### Как открыть страницу на телефоне

1. `npm run agent -w spike` в одном терминале — воркер должен быть
   зарегистрирован раньше, чем создана комната.
2. `npm run token -w spike` в другом — печатает имя комнаты и пишет ссылку
   в `spike/last-url.txt`.
3. Открыть `spike/last-url.txt` самому и передать ссылку на телефон
   (буфер обмена, локальная синхронизация — любым способом, который не
   оставляет её в чате, задаче или истории консоли). Ссылка живёт 2 часа.

Ссылка содержит значение `WEB_HOST`, значение `LIVEKIT_URL` и живой токен с
правом создания комнаты. Поэтому её нет в выводе команды: stdout попадает в
транскрипты агентов и журналы задач, а оттуда — куда угодно.

### [!] Вывод воркера содержит адрес сервера

`npm run agent -w spike` печатает лог `@livekit/agents`, и библиотека при
регистрации воркера сама выводит поле `url` — то есть значение
`LIVEKIT_URL`, реальный хостнейм. Скрыть это на стадии 0 нечем: логгер
внутри библиотеки. Поэтому вывод этой команды нельзя целиком вставлять в
доки, задачи, чат и публичные места — только выдержки без строк с адресом.
На стадии 1 в `apps/voice-agent` заводится обёртка логгера, вырезающая
`url` и подстроку `wss://`.
